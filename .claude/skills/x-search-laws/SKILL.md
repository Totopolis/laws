# Поиск по кодексам и законам РФ

Скилл отвечает на вопросы по действующему законодательству, находя конкретные статьи
в `data/`. Механика уже реализована в `src/laws_mcp/` — задача скилла в том, чтобы
**правильно задать запросы, проверить найденное по полному тексту и честно отчитаться**,
что закон говорит, а чего в нём нет.

Скилл работает в репозитории с кодексами (`src/laws_mcp/cli.py` в наличии).
Ничего не качает и не меняет на диске. Тексты и индекс поставляются вместе
с репозиторием; если их нет, сборка неполная — скажи об этом, чинить нечем.

## Как запускать

Из корня репозитория, с `PYTHONPATH=src`:

```bash
PYTHONPATH=src PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m laws_mcp.cli "запрос"
```

На Windows путь к python — `.venv/Scripts/python.exe`; системный python не подойдёт,
зависимости стоят только в `.venv`.

**Задавай все запросы одной командой.** Модель весит 2,3 ГБ и грузится ~4,5 секунды,
а сам поиск занимает 0,2 с. Пять отдельных вызовов — это 25 секунд, один вызов
с пятью запросами — 6 секунд:

```bash
... -m laws_mcp.cli "неуплата алиментов ответственность" "злостное уклонение от алиментов" "лишение родительских прав за неуплату"
```

Полезные флаги:

```bash
--top=5                 сколько статей на запрос (по умолчанию 10)
--code=uk-rf            искать только в этих кодексах, можно повторять флаг
--fragment=0            без фрагментов текста, только заголовки — когда нужен обзор
--json                  машинный вывод
--repealed              включая утратившие силу статьи (по умолчанию только действующие)
--mode=fts              поиск по словам вместо смысла — для точной цитаты
--rerank                пересортировать выдачу cross-encoder'ом (+4 с, см. ниже)
--article uk-rf:105     показать статьи целиком (несколько через пробел)
--codes-list            список кодексов со slug'ами
```

## Шаг 1 — сформулировать запросы

Ищет **смысловой** поиск, а не подстрока. Пиши запрос так, как спросил бы человек
(«что грозит за неуплату алиментов»), а не ключевыми словами («алименты 157»).

Задавай **несколько формулировок сразу** — это дёшево (0,2 с на запрос) и заметно
надёжнее одной. Полезно комбинировать:

- бытовую формулировку вопроса пользователя;
- юридический термин, если он известен («суброгация», «неосновательное обогащение»);
- предполагаемое последствие («ответственность за …», «размер штрафа за …»).

Если пользователь назвал кодекс — добавь `--code=`, это убирает похожие статьи из соседних
кодексов. Список slug'ов даёт `--codes-list`; часто нужные: `uk-rf`, `koap-rf`, `tk-rf`,
`sk-rf`, `zhk-rf`, `nk-rf-chast-2`, `gk-rf-chast-1`…`gk-rf-chast-4`.

Когда пользователь прямо называет статью («статья 105 УК»), поиск не нужен — сразу
`--article uk-rf:105`.

### Когда добавлять `--rerank`

Пересортировка пропускает 30 кандидатов через cross-encoder, который читает пару
«запрос + статья» целиком. Она нужна там, где **вопрос задан бытовыми словами, а норма
названа абстрактно** и общих слов между ними нет: «сосед залил квартиру» → «Общие основания
ответственности за причинение вреда», «работник сломал оборудование» → «Материальная
ответственность работника». На таких запросах recall@10 растёт с 62% до 75%, MRR — с 0,29
до 0,45.

Не включай её по привычке: на обычных запросах она ничего не добавляет (MRR даже чуть ниже:
0,809 против 0,839), а стоит **около 5 секунд** сверх обычного поиска.

Практическое правило: сначала обычный поиск; если в выдаче нет ничего похожего на ответ
или пользователь описывает житейскую ситуацию, а не юридическую — повтори с `--rerank`.
Держи в уме предел: пересортировка меняет порядок 30 найденных статей, но не находит новых.
Если нужной статьи в выдаче нет вообще, поможет только другая формулировка запроса.

## Шаг 2 — прочитать найденное целиком

Фрагменты в выдаче обрезаны и годятся только для отбора кандидатов. **Прежде чем
отвечать по существу, открой статьи целиком** — одной командой на все нужные:

```bash
... -m laws_mcp.cli --article sk-rf:115 uk-rf:157
```

Это обязательно: в кодексах ответ часто зависит от оговорки в другой части статьи
(«за исключением случаев, предусмотренных пунктом 3»), которой во фрагменте не видно.

Обрати внимание на поля:

- `status` — `действует` или `утратила силу`. По умолчанию ищутся только действующие,
  но `--article` покажет любую; проверяй статус перед цитированием.
- единица (`часть 2`, `пункт 6`) — на неё и ссылайся, а не на статью целиком.
- иерархия (раздел → глава) — помогает понять область применения.

## Шаг 3 — отчитаться

Отвечай **со ссылкой на конкретную единицу**: «ст. 115 СК РФ, п. 2» — и цитируй
формулировку закона, а не пересказывай по памяти. Если нашлось несколько релевантных
статей в разных кодексах (типичная ситуация: одно деяние даёт и административную,
и уголовную ответственность) — покажи все и объясни разницу.

Обязательно скажи, если:

- ничего релевантного не нашлось — так и скажи, не подставляй похожую статью;
- вопрос выходит за рамки того, что лежит в индексе. Состав меняется от сборки к сборке:
  где-то это только 24 кодекса, где-то к ним добавлены федеральные законы. **Проверяй
  составом, а не памятью** — `--codes-list` (в MCP `list_codes()`) печатает все документы
  снапшота. Если нужного закона там нет, так и скажи: найти его нельзя;
- ответ зависит от подзаконных актов, судебной практики или разъяснений Пленума ВС —
  этого в индексе тоже нет.

Указывай дату выгрузки, на которую верен ответ: право меняется. Дату и редакцию каждого
кодекса печатает `--codes-list`.

Не давай юридических советов «как поступить» — излагай, что написано в законе,
и оставляй решение пользователю.

## Особенности запуска

- **Один вызов CLI — около 6 секунд**, из них ~5,5 с уходит на загрузку ONNX-модели
  (2,3 ГБ), а каждый запрос внутри вызова стоит 0,2 с. Таймаут ставь от минуты.
- **Бэкенд менять не нужно**: по умолчанию CLI считает на CPU через onnxruntime.
  `--backend=torch` использует GPU, но для разового запуска он втрое медленнее
  (19,5 с против 6,1 с — инициализация CUDA дороже самого поиска).
- **Вывод в UTF-8**: на Windows обязателен `PYTHONIOENCODING=utf-8`.
- **`--top=10` по умолчанию с фрагментами по 300 символов** — на трёх запросах это уже
  заметный объём. Для широкого обзора бери `--fragment=0`, для разбора — `--top=3`.
- Скилл ничего не меняет на диске, запускать его безопасно сколько угодно раз.

## Типичные сбои

- **`нет индекса в …/index`** — индекс не поставлен вместе с репозиторием. Пересчитать
  его здесь нечем: скажи об этом пользователю, нужна полная сборка от поставщика.
- **`ModuleNotFoundError: lancedb` / `onnxruntime`** — запущен не тот python.
  Нужен `.venv/Scripts/python.exe` и `PYTHONPATH=src`.
- **`нет файла модели в …`** — не выполнен `/x-prepare-system`: модель в репозиторий
  не входит и качается отдельно (2,3 ГБ). Модель нужна именно fp32: int8-сборка даёт
  векторы, не совпадающие с индексом, и поиск молча промахивается.
- **Выдача не по теме** — переформулируй запрос ближе к языку кодекса и добавь `--code=`.
  Если ищешь точную цитату, а не смысл, пробуй `--mode=fts`.
- **Статья не находится по номеру** — проверь формат: индекс через точку (`uk-rf:53.1`),
  и это должен быть номер статьи, а не пункта.
