# Кодексы и законы РФ: поиск по смыслу

Репозиторий даёт офлайн-поиск по законодательству Российской Федерации (24 кодекса и 563 закона): вопрос обычными словами —
в ответ конкретные статьи. Ничего не качается из сети во время работы, всё считается локально
на процессоре. Первое знакомство и команды для человека — в `README.md`, здесь то, что нужно
знать при работе с кодом.

```
data/       тексты по статьям: data/<раздел>/<slug>/st-105.json, реестр — data/index.json
            (раздел документа — поле dir реестра: codex/ для кодексов, fz/ для законов)
CATALOG.md  перечень всех документов сборки: редакция, число статей, slug
index/      векторный индекс LanceDB (laws.lance) — по нему идёт поиск
src/laws_mcp/  поиск: server.py (MCP), cli.py (терминал), search.py (ядро)
```

Снапшот один, папок-дат нет. **Тексты выгружены 2026-09-17**, всего 29 039 статей
в 587 документах (24 кодекса и 563 закона); редакция каждого по отдельности — в `data/index.json`
и в `CATALOG.md`.

## Как пользоваться поиском

Скиллы: `/x-prepare-system` — развернуть на новой машине, `/x-search-laws` — искать,
`/x-run-mcp` — поднять MCP-сервер. Если работаешь без них:

```bash
PYTHONPATH=src PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m laws_mcp.cli "вопрос" "ещё вопрос"
PYTHONPATH=src PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m laws_mcp.cli --article uk-rf:105
PYTHONPATH=src PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m laws_mcp.setup_check
```

На Linux/macOS интерпретатор — `.venv/bin/python`, `PYTHONIOENCODING` не нужен.

Два правила, которые сильно влияют на результат:

1. **Задавай несколько формулировок за один запуск.** Модель грузится ~5 секунд, а каждый
   следующий запрос внутри вызова стоит 0,2 с. Пять отдельных вызовов — это 30 секунд,
   один вызов с пятью вопросами — 6.
2. **Перед ответом по существу открывай статью целиком** через `--article`. Фрагменты
   в выдаче обрезаны, а в законе ответ часто зависит от оговорки в другой части статьи
   («за исключением случаев, предусмотренных пунктом 3»), которой во фрагменте не видно.

## Как это устроено

Каждая статья и каждая её структурная единица (часть, пункт) заранее превращены в вектор
моделью **Qwen3-Embedding-0.6B** и лежат в `index/`. Запрос превращается в такой же вектор,
и находятся ближайшие — поэтому совпадения слов не требуется.

Индексируются **два уровня**: статья целиком (о чём она в принципе) и её части по отдельности
(чтобы попадать точно в нужный пункт). Записи одной статьи в выдаче схлопываются в один
результат.

В эмбеддинг идёт не голый текст, а с контекстом: документ, иерархия, заголовок статьи, адрес
единицы. Без этого пункт «ж) группой лиц по предварительному сговору» — бессмысленный вектор.

**Полные тексты в индексе не дублируются** — они читаются из `data/` по имени файла. Поэтому
выдача всегда соответствует поставленным текстам и не может с ними разойтись.

### Режимы поиска

По умолчанию — чистый векторный поиск (`dense`). Это не «настройка по умолчанию, которую
стоит покрутить», а результат замера на 32 контрольных запросах: гибрид с полнотекстовым
поиском (`hybrid`) проигрывает почти везде, потому что модель уверенно берёт и точные термины
вроде «преюдиция» или «эмансипация». Режим `fts` полезен разве что для поиска точной цитаты.

**Пересортировка** (`--rerank`, `rerank=true`) прогоняет 30 найденных кандидатов через
cross-encoder, который читает пару «вопрос + статья» целиком. Она нужна там, где вопрос задан
бытовыми словами, а норма названа абстрактно: «сосед залил квартиру» → «Общие основания
ответственности за причинение вреда». На таких запросах recall@10 растёт с 62% до 75%.
Стоит около 4 секунд, поэтому выключена по умолчанию — включай, когда обычный поиск вернул
не то или вопрос описывает житейскую ситуацию.

Проверить качество после любых изменений: `python -m laws_mcp.evaluate`.

### Модель

Нужна именно сборка **fp32** (2,3 ГБ, `onnx-community/Qwen3-Embedding-0.6B-ONNX`,
файлы `onnx/model.onnx` + `model.onnx_data`). Не подменяй её на int8 ради размера: её векторы
не совпадают с индексом (косинус 0,73 вместо 1,0), поиск при этом **не падает**, а молча
выдаёт ерунду. Поймать это можно только метрикой — `setup_check` для того и гоняет
контрольные запросы.

Модель-переоценщик (реранкер) наоборот берётся в int8 и это нормально: она выдаёт оценку
пары, а не вектор в общем с индексом пространстве, и совпадать ей не с чем.

Модели в репозиторий не входят (`models/` в `.gitignore`) — их скачивает
`setup_check --install`.

## Ограничения, которые нужно называть пользователю

- В индексе — **кодексы и федеральные законы** (24 кодекса и 563 закона); полный перечень с реквизитами
  и датами редакций лежит в `CATALOG.md`, состав в машинном виде — `list_codes()`. За его
  пределами остаются подзаконные акты (постановления Правительства, приказы ведомств),
  региональное законодательство, судебная практика и разъяснения Пленума ВС. Если вопрос
  упирается в них, скажи об этом прямо, а не подставляй похожую статью.
- Ответ верен **на дату выгрузки — 2026-09-17** (она же в `data/index.json`, поле
  `fetched`). Указывай её, когда отвечаешь по существу.
- Это поиск, а не консультация: излагай, что написано в законе, со ссылкой на конкретную
  часть или пункт, и не давай советов «как поступить».
- По умолчанию ищутся только действующие статьи; утратившие силу — с `--repealed`.

## Настройки окружения

`LAWS_ROOT` — корень данных (обязателен, если процесс запускается не из папки репозитория),
`LAWS_INDEX`, `LAWS_PROCESSED`, `LAWS_MODEL_DIR`, `LAWS_RERANKER_DIR` — отдельные пути,
`LAWS_BACKEND` — `onnx` (CPU, по умолчанию) или `torch` (видеокарта, если она есть; для
одиночных запросов медленнее — инициализация CUDA дороже самого поиска).

## Развёртывание

В комплекте `Dockerfile`: собирает образ с данными, индексом и моделями внутри, так что
контейнеру не нужна сеть.

```bash
docker build -t laws-mcp .
docker run -i --rm laws-mcp     # -i обязателен: MCP общается через stdin/stdout
```

Модели копируются в образ из `models/`, поэтому перед сборкой нужно выполнить
`setup_check --install`. Размер образа около 3,5 ГБ, из них 2,8 ГБ — модели.

Если пользователь просит развернуть это на сервере, поднять веб-интерфейс или встроить
в свою систему — берись: ядро поиска в `search.py` не зависит ни от MCP, ни от CLI,
у обоих один и тот же класс `Searcher`.
